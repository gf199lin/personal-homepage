# 03｜项目经历

本文件区分已完成/正在更新的项目、历史迭代和仅选择尚未启动的项目。不可将计划写成成果。

## 项目一：个人主页与数字分身

- 主页：<https://gf199lin.github.io/personal-homepage/>
- 用户从零开始制作个人主页，不是直接套用现成模板。
- 项目对用户而言不只是技术作业，也是一种个人表达空间：整理照片、经历、兴趣，并通过视觉设计呈现自己的风格。
- 用户很在意页面是否好看、有辨识度，想让它有趣、感性、有个人特色。

### 设计风格形成

- V1 最初以海洋蓝为主。
- 用户浏览线上网站设计资源时，看到一个很喜欢的设计风格，对方也使用蓝色与象牙白的配色，于是尝试采用类似的配色。
- 用户喜欢的不只是配色，也欣赏参考网站的布局、字体和构图；但认为完整复刻难度太高，尝试后放弃照搬，转而吸收喜欢的视觉元素。
- 不要声称用户复制了参考网站；准确描述为受到启发并自行调整。

### 迭代过程（来自用户提供的课程报告，报告日期 2026-09-29）

- 项目经历 V1 至 V4 多轮迭代。
- V1：单页主页，包含头像、个人信息卡片、近期作品/兴趣等内容，以及右侧数字分身聊天区域。
- V2：重构视觉和页面结构，采用象牙白与蓝色、圆角导航、萨摩耶线稿背景；加入音乐卡片、留言墙原型、关于我/高中/深圳等内容。报告记录 54 项改动。
- V3：部署至 GitHub Pages；留言墙接入后端，支持照片、便签、视频和评论；增加反馈表单。报告记录 11 次迭代。
- V4：分为自主迭代与反馈驱动迭代两个阶段。
- 报告记录当时一次回归测试为 51 项通过、0 项失败，测试设备视口包括桌面 1440×1000 和移动端 390×844。该数据是 2026-09-29 报告时的测试结果，不代表当前版本永远无问题。

### 用户最喜欢的主页功能

用户最喜欢留言墙：
- 喜欢和朋友互动。
- 朋友会在墙上留下文字和照片。
- 有些照片来自用户自己的主页/照片收藏，有些由朋友自己提供。
- 用户既喜欢照片本身，也喜欢朋友留下痕迹、参与互动的感觉。
- 留言墙让主页从单向展示变成共同留下记忆的空间。

### 用户的项目工作方式

- 不会照单全收 AI 或访客的建议。
- 会先判断反馈描述的问题是否真实存在，再决定是否采用对方提出的解决办法。
- 会考虑影响和实现成本，结合项目目标决定优先级。
- 会复现问题、检查实际效果，再决定是否修改。
- 用户保留最终决策权；AI 帮助总结、提出方案、修改代码、制作测试清单和执行测试。
- 用户曾反思反馈收集方式：仅写“留言”导致留言墙中有很多普通留言，却没有足够有效反馈；之后意识到需要用更明确的问题引导访客反馈。
- 曾发现自己对显示颜色的诊断存在未经测量就先入为主的问题，认识到应先测量、再提出假设。
- 版本迭代中有保存旧版本作为回滚点、记录改动和截图、发布后核对文件/部署版本等习惯。

## 项目二：Bear Run 体感小游戏

- 仓库：<https://github.com/gf199lin/bear-run/>
- 在线页面：<https://gf199lin.github.io/bear-run/>
- 项目背景：项目制课程作业。游戏开发方向由用户和队友共同选择，并非老师直接指定。
- 选择体感游戏的原因之一是老师提供了雷达硬件，团队觉得既然有设备就应该尝试使用。
- 项目目前处于 MVP（最小可行产品）阶段，仍在更新；不能写成已经完全结束。

### 用户主要负责

- 游戏机制与玩法设计
- 前端页面
- 游戏逻辑
- UI 设计
- 测试与调试
- 项目协调

雷达硬件模块本身由另一位组员负责。用户参与雷达测试、联调和数据检查，但不能写成用户独立开发了雷达硬件或雷达底层模块。

### 难点与解决过程

- 最大困难是和负责雷达的组员协调，并把雷达数据稳定接入游戏。
- 雷达连接曾经不稳定，有时可用、有时不可用。
- 团队通过反复调试、修改接口、调整代码、测试数据等方式解决问题。
- 用户认为目前雷达集成已经稳定。

### 最有成就感的时刻

两台雷达都成功连接游戏，团队真正用雷达玩起来。虽然精度并不高，但大家很开心，觉得之前的调试有了意义。对用户来说，这是从代码和想法走向现实互动的体验。

### 学到的东西

- 团队协作和跨模块沟通。
- 项目不是只完成自己负责的部分，还需要理解接口、协调联调。
- 更完整地经历了从想法选择、设计、分工、开发、硬件集成、测试到持续更新的项目流程。

### 技术信息待核实

不要仅凭旧对话中未经用户确认的仓库推断，写入未经验证的具体玩法/技术细节。Agent 可在检查仓库后再补充，例如游戏角色、关卡机制、渲染技术、输入方式等。

## 项目三：夜间异常行为检测

- 用户选择的课程项目方向：夜间异常行为检测。
- 应用场景：养老机构和居家夜间照护。
- 方案设想涉及毫米波雷达、非摄像头方式监测人体活动及呼吸相关信号。
- 任务方向包括床区几何自校准、区分正常起身/翻身/坐起与异常行为、连续夜间监测和事件验证，并形成算法、数据集与评估报告。
- **当前状态：已选择，但尚未启动；小组分工尚未确定。**
- 用户目前还没有深入理解项目细节，不应把上述任务描述写成用户已经掌握或完成的工作。

## 项目经历总原则

- 主页：用户从零搭建并持续迭代，重点体现视觉表达、用户判断和 AI 协作。
- Bear Run：用户负责游戏前端与玩法等，雷达模块由队友负责，用户参与联调。
- 夜间异常行为检测：只记录为已选方向、尚未开始。
