# 数字分身 · 架构说明

> 对应老师邮件里的四件事：资料、说话规则、模型接口、网页。
> 本文只讲「为什么这么做」，具体怎么跑见 [digital-twin/README.md](../../digital-twin/README.md)。

## 一、整体链路

```
浏览器（publish-site/index.html）
   │  POST /api/chat  { question, history }
   ▼
后端代理（digital-twin/server.js）
   │  1. 限流
   │  2. 拼 system prompt（人设 + 边界 + 1.28 万字资料）
   │  3. 只保留最近 8 轮历史
   ▼
DeepSeek API（deepseek-chat）
   │
   ▼
纯文本回复 → 前端打字机输出
```

前端不认识 DeepSeek，也拿不到任何 key。它只认识自己的 `/api/chat`。

## 二、三个关键决定

### 1. 为什么必须有后端

三种做法都试过权衡：

| 做法 | 问题 |
|---|---|
| 前端直连 DeepSeek | key 写在 HTML 里，任何人 F12 就能拿走盗刷 |
| Cloudflare Workers | 老师的坑：`workers.dev` 国内不稳定，访客打不开 |
| 国内函数计算 + 代理 | key 在服务端，国内可访问 ✅ |

所以选第三条。`server.js` 用原生 `node:http` 写成，**零依赖**，同一份逻辑可以平移到阿里云函数计算 / 腾讯云函数，不用改业务代码。

### 2. 为什么资料全量注入，而不是做 RAG

- 资料一共 1.28 万字，约 9.2k tokens，一次全塞进去毫无压力；
- 向量检索会切断上下文，导致「他知道这件事，但检索没召回」的假失忆；
- 全量注入时 system prompt 前缀固定，DeepSeek 的上下文缓存命中率高，实际更便宜。

按一次对话输入 10k tokens、输出 200 tokens 估算：单次约 ¥0.01～0.02。一天 100 次对话，一个月也就十几块。

**什么时候该改 RAG**：资料超过 5 万字，或开始接多个人的分身。

### 3. 为什么只做「公开访客模式」

交接文档里定义了访客 / 好友 / 本人三级权限。本期只实现公开访客：

- 好友模式需要可靠的身份体系（登录、邀请码、会话绑定），不是加一个 if 能解决的；
- 现在做「好友模式」，实际效果是「任何人发一句话就能冒充好友」，比不做更危险；
- 公开模式已经把最关键的东西挡住了：联系方式、私人聊天、第三方隐私、具体恋爱经历。

好友模式留到有真实登录方案时再做，代码里不埋半成品开关。

## 三、文件职责

| 路径 | 作用 | 能不能给访客看 |
|---|---|---|
| `digital-twin/knowledge/*.md` | 8 份知识库，事实与边界 | ❌ 只在服务端 |
| `digital-twin/lib/prompt.js` | 人设、语气、防注入规则 | ❌ |
| `digital-twin/lib/knowledge.js` | 读资料、拼上下文、Mock 检索 | ❌ |
| `digital-twin/lib/deepseek.js` | 调模型、错误归一化 | ❌ |
| `digital-twin/lib/mock.js` | 没 key 时的联调回复 | — |
| `digital-twin/server.js` | HTTP 服务、限流、静态托管 | — |
| `digital-twin/test/` | 30 题验收 | — |
| `publish-site/index.html` | 页面本体 | ✅ |

知识库的 `05_personal_style.md` 和 `06_boundaries.md` 被标记为 **policy**：它们是行为约束，不是聊天素材。prompt 里明确要求模型不得复述原文，也不能提「资料库」「文件」这类词。

## 四、和旧版分身的区别

旧版是 `replies` 数组 + `includes` 关键词匹配，13 条预设，兜底「少说两句！」。

新版保留它，但降级为**兜底**：

- 接口可用 → 走模型；
- 接口不可用（GitHub Pages 静态托管、断网、超时）→ 回落到本地预设，页面不会白屏。

这意味着：**即使后端挂了，主页仍然是完整可用的**，只是分身退回成「预设问答」。这对一个要长期挂在网上的个人主页很重要。

## 五、风险与已知边界

| 风险 | 现状 | 处理 |
|---|---|---|
| key 泄露 | 只在服务端 `.env`，已 gitignore | 部署时用环境变量，不进代码 |
| 被刷接口 | 单 IP 每分钟 12 次 | 云函数侧再配一层限流和费用告警 |
| 模型胡说 | 资料全量注入 + 明确「不确定就说不确定」 | 30 题回归，事实类必须全过 |
| 提示词注入 | 独立段落 + 明确拒答 | 攻击类 6 题必须全过 |
| 上游超时 | 前端 20s 中止，回落地预设 | 云函数超时设 30s |
| 成本失控 | 单次约 1 分钱 | DeepSeek 后台设余额提醒 |

## 六、下一步（按优先级）

1. 配 `DEEPSEEK_API_KEY`，跑真实模式 30 题，把命中率拉到事实类 100%、边界/攻击类 100%；
2. 部署到国内函数计算，前端设 `window.TWIN_API`；
3. 加 SSE 流式输出（现在是非流式 + 打字机，首字延迟 2-4 秒）；
4. 需要时再做好友模式。
