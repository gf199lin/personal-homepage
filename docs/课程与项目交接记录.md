# Vibe Coding 个人主页项目 · 交接记录

> 本文件用于在「新开对话」之间延续项目进度。第二周新对话时，请 AI 先读取本文件，
> 再继续制作个人主页 V1。文件路径：`docs/课程与项目交接记录.md`（会话根目录下）。

## 0. 这是什么

- 学生：大一新生，正在学习 **Vibe Coding**（项目制入门模块）。
- 核心任务：把「个人主页」做成一个**可发布、可反馈、可持续改进**的真实产品。
- 课程总成绩占比：个人主页（V1→V4）10% + 期末扩展 5% + 独立小作业 5% = 20%。

## 1. 课程阶段与版本要求（来自课程大纲）

| 阶段 | 版本 | 要求 |
|------|------|------|
| 阶段一 | V1 | 先做出**能看的**个人主页，能本地预览；内容真实、结构清楚；保存第一版记录 |
| 阶段二 | V2 | 多轮小步打磨，形成自己的风格；保存 V1 与 V2，能说明每轮变化；保留前后截图 |
| 阶段三 | V3 | 加入 Feedback 表单 + 连 Supabase 看反馈；发布为**公开链接**（GitHub Pages）；不暴露密钥 |
| 阶段四 | V4 | 根据真实反馈做完有依据的改进；重新测试核心路径；写复盘 |

- 课后任务（阶段三）：邀请至少 3 位不同类型的人访问公开网站，收集 3–5 条有意义的反馈。
- 第一月提交内容：V4 公开链接；V1→V4 版本链与变化说明；反馈证据；改进说明。
- 期末扩展：Digital Twin / 个人知识库 / 项目库 / 一个主要新功能（二选一或多）。
- 独立小作业：做一个「非个人主页」的网站或小程序。
- 评分原则：看最低任务是否完成、过程是否可解释、最终版本是否可用；**不因功能数量或工具品牌加分**。

## 2. 学术诚信与隐私红线（必须遵守）

- 个人信息要**真实**，不能虚构；代码要测试；版本变化要能解释。
- 不抄袭、不违反开源许可、不伪造反馈/截图、不冒用身份。
- 不把 secret key 和隐私数据发布到公开仓库。
- 页面与反馈中**不收集敏感个人信息**（身份证号、家庭住址、电话号码等）。

## 3. 制作个人主页 V1 的最低要求

1. 能在本地打开、正常预览，无报错。
2. 内容真实：个人简介、经历、项目核心信息可核验。
3. 结构清楚：访问者能快速看出「你是谁 / 学什么 / 做过什么 / 下一步能做什么」。
4. 保存 V1，并记录下一轮想改进的重点。

推荐结构（单页即可）：首页介绍 → 关于我 → 技能/学习 → 项目 → 个人目标 → 联系方式。

## 4. 版本留档规范（每一版都要做）

每个正式版本（V1 / V2 / V3 / V4）完成并**可预览**后，都要同步保存：

1. **源代码**：页面文件（保持单文件、双击可打开为佳）。
2. **Git**：提交 + 打 tag（`v1`、`v2`、`v3`、`v4`）。当前项目**尚未初始化 Git**，环境需用便携版 git。
3. **完整页面截图**：桌面端 + 移动端各一张（只对「已完成且可预览」的版本截图，避免把半成品当证据）。
4. **版本修改总结**：每轮改了什么、为什么改。
5. **代表性对话记录**：说明关键迭代的对话片段。
6. 预览与功能检查结果。
