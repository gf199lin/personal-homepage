## 一、先明确一件事：发布入口用哪个文件

课件第 33 页说「入口文件：index.html（访问根路径时默认加载）」。但你项目里现有两个 HTML，**不能想当然地用 `homepage/index.html`**：

| | `homepage/index.html` | `homepage/lcy homepage.html` |
|---|---|---|
| 行数 / 大小 | 1636 行 / 1.13 MB | 2763 行 / 1.18 MB |
| 反馈入口与表单 | **没有** | 有 |
| Supabase 接入 | **没有** | 有 |
| 大图预览 / 返回顶部 | **没有** | 有 |
| 跳出发布目录的图片引用 | **24 处** | 0 处 |

`index.html` 是个**比 V2 还早的旧版本**。如果直接把 `index.html` 发上去，公众打开会看到一个**没有反馈入口**的网站，V3 的核心目标直接落空。

**结论：用 V3 页面发布，只是文件名必须叫 `index.html`**（因为访问根路径 / 时服务器默认加载 index.html）。这一步我已经做好了，见下。

## 五、GitHub 操作步骤（课件第 38 页流程）

账号操作这一步要你自己做（课件第 30 页分工：你负责账号操作与验收）。

1. **准备发布文件** —— 已完成，见 `publish-site/`
2. **创建仓库并上传**
   - 新建一个仓库，建议名字好记，例如 `my-homepage`（**本次实际使用：`personal-homepage`**）
   - 可见性选 **Public**
   - 把 `publish-site/` 里的 **`index.html` 和 `assets` 文件夹**一起拖进上传区
     - 注意：要传 `assets` **整个文件夹**，不能只传里面的图片，否则路径对不上
   - 上传后仓库根目录应直接看到 `index.html` 和 `assets/`（**不要再套一层文件夹**）
3. **Settings -> Pages 配置发布来源**
   - Source 选 `Deploy from a branch`
   - Branch 选 `main`，目录选 `/ (root)`
   - Save
4. **查看部署状态** —— 回到 Pages 页面，等它显示已发布（通常一两分钟）
5. **打开最终网址验证**
   - 项目页网址形如：`https://你的账号.github.io/仓库名/`
   - 若仓库名恰好是 `你的账号.github.io`，则网址是 `https://你的账号.github.io/`（用户页，站点在根路径）

### 过程中踩到的三个坑（留档，以后再发布直接照做）

1. **`Commit changes` 按钮在页面最底部** —— 拖完文件必须把页面滚到最底部，才能看到并点中那个绿色按钮；否则文件不会真正上传。第一次就是卡在这里（还以为提交成功了，其实仓库一直是空的）。
2. **启用 Pages 后没有自动出现部署记录** —— 在仓库根新建一个空文件 `.nojekyll`（文件名前面有点，内容随便写一个字符），提交后立刻触发构建，约 1 分钟上线。它同时关闭 Jekyll 处理，纯静态站点本来就该这么做。
3. **`Save` 按钮是灰的不代表出错** —— Pages 配置一旦保存过，下拉框的值等于已保存值，`Save` 就会保持禁用，这是正常状态。要判断是否真的生效，看有没有部署记录，而不是看按钮颜色。

**另一条经验**：GitHub 的 `/settings/...` 设置页，**未登录访问时返回 404**（不是跳转登录页）。所以在没登录的浏览器里打开设置页看到 404，属于正常现象，换到已登录的浏览器即可。

### 日后更新网站

改动后用 `Add file` → `Upload files` 覆盖同名文件，**记得滚到底点 `Commit changes`**；Pages 会自动重新构建。若线上没立刻变化，先等一两分钟再 `Ctrl + F5` 强刷（Pages 带 CDN 缓存）。
