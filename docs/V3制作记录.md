## 三、V3 协作规则

1. 课件原则：**不借机重做网站**。V3 只做「功能 + 发布」，不改 V1/V2 的设计。
2. 用户负责：需求、账号操作（Supabase / GitHub）、核对与验收。
3. DeepWorks 负责：辅助生成代码、解释脚本、定位问题；**先说明修改范围，用户确认后再动手**。
4. 每次实际改动都记录 Prompt 原话、改动位置、前后差异、动机/参考来源、原创化处理与验证结果。
5. 改动只落在 `homepage/lcy homepage.html`；未经用户确认不动 `homepage/index.html`。
6. 验收标准（课件 Part 5）：能打开公开网址、访客能提交反馈、你能在后台看到这条记录、提交过程有基本的状态与错误提示。
7. 「真正确认存进去了」= 做一次带**唯一标记**的测试提交，回到 Table Editor 找到同一条记录，字段完整、时间正确；不能只看网页提示「提交成功」。
8. 失败与重复点击：提交中显示状态、按钮禁用；确认成功后才提示成功；失败时保留已输入内容并提示可重试。
9. 发布后提醒：GitHub Pages 有 CDN 缓存，更新不一定立即生效，先确认「线上文件是否已更新」再排查。
10. **本地成功 ≠ 线上已经成功**，发布后必须用最终网址在电脑与手机上各提交一次。

## 四、安全底线（课件 Part 2 / Part 4）

- `publishable key`（旧称 anon key）：可公开，允许放进前端代码。
- `secret key`（旧称 service_role key）：高权限、绕过 RLS，**永远不进前端 / 公开仓库 / 课件 / 截图**，也不发给 AI。
- 数据库密码同样不出现在网页或公开仓库。
- 不向 AI 提供管理员密码或高权限密钥。
- 红线：不为消除报错而**关闭 RLS** 或放开全部权限。
- 密钥若不慎外传：立即在 Supabase 后台轮换（重置）。
- 若反馈可能包含个人信息：公开仓库里只放代码，反馈数据只留在你自己的后台。
- 长期公开使用需额外防滥用（限流 / 验证码），本课不要求，但要知道「防重复点击 ≠ 防恶意刷留言」。
